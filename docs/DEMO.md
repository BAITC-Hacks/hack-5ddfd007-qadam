# QADAM: сценарий демонстрации (2–3 минуты)

Демонстрировать локальное приложение после `npm run build` и `npm start` на http://127.0.0.1:3000.

1. **0:00–0:20.** QADAM подбирает до трёх существующих профилей, не создаёт подрядчиков и не бронирует услуги. Показать форму: город, дата, формат, категория, бюджет; язык и длительность необязательны. Каталог анонимизирован, не является проверенной базой реальных поставщиков.
2. **0:20–0:50.** «Много вариантов»: Алматы, ведущий, корпоратив, 10 октября, 1 200 000 ₸, русский, 5 часов. Из 10 профилей проходят 4; показаны 3 в порядке HK-88430, HK-29829, HK-27222. Показать стартовые цены, объяснения по конкретным ограничениям, раскрыть фрагмент описания. Календарь исключил 4 профиля.
3. **0:50–1:10.** «Редкая категория»: Алматы, флорист, свадьба, 5 октября, 500 000 ₸, русский. Только HK-39372; второй флорист занят. Обратить внимание на отметку восстановленной цены.
4. **1:10–1:35.** «Нет результата»: в Астане нет декораторов — `no_category_in_city`. Затем «Пример: занятый банкетный зал»: категория есть, но единственный зал занят 14 ноября — `no_eligible_candidates`. Это разные причины пустого результата.
5. **1:35–2:05.** «Проверить 10 октября», затем «Проверить 11 октября»: для фотографов Алматы меняется набор 3 → 2, по реальным `busy_dates`. Не случайная перестановка.
6. **2:05–2:30.** Повторить «Много вариантов»: порядок ID тот же. Показать `npm test`, `npm run validate:data`, README и реальную историю Git.

AI в текущей проверенной конфигурации отключён: ключа нет, проверен детерминированный fallback. Не выдавать его за вызов модели. Для live AI отдельно настроить ключ/модель, успешно выполнить `npm run verify:ai`, затем включить `AI_VERIFIED=true` и перезапустить сервер. При отказе модели приложение сохраняет тот же список и честно маркирует объяснения по правилам.

Скриншоты создаются командой `npm run test:e2e` в `artifacts/`. Они локальные и не публикуются автоматически. Автоматизированная браузерная проверка не заменяет ручную проверку участником.
