# QADAM — умный подбор подрядчиков

HackAlem AI 2026, трек **79-lite**. Одностраничное приложение на русском подбирает **0–3 существующих профиля** из оригинального анонимизированного каталога организаторов по городу, дате, формату, категории, бюджету, а также необязательным языку и длительности.

Без бронирования, контактов, аккаунтов, расширения каталога, базы данных и вымышленных рекомендаций. Полностью работает без платного API: правила выбирают профили и формируют объяснения; опциональная модель может только переформулировать объяснения.

## Оригинальные данные и права доступа

Источник — файл организаторов, предоставленный участником локально: **`hackathon dataset anonymized.csv`**. Файл не изменяется и не копируется в публичный каталог. В репозитории не найдены лицензия CSV или разрешение на распространение. Поэтому `*.csv` исключены из Git; перед публикацией или передачей жюри нужен разрешённый организаторами способ получения исходного файла. Нельзя считать репозиторий самостоятельно воспроизводимым без доступа жюри к этому CSV.

Ожидаемый SHA-256 исходных байтов:

```text
6a724b6b7dfb5973343e68ba18dadb60fc807d87e3d78f03ee86fb26cb089f7d
```

66 записей, 13 колонок, 17 категорий. Города: Алматы — 50, Астана — 15, Зарубежье — 1. 13 синтетических профилей, 18 восстановленных цен, 8 восстановленных городов, 9 пустых `max_hours`. Значение «Зарубежье» сохранено как отдельное значение исходного каталога и не трактуется как город Казахстана.

Календарь ограничен **2026-09-23…2026-12-31 включительно**. `csv-parse/sync` обрабатывает RFC4180, запятые и переводы строк внутри кавычек. Списки разделены `|`; флаги True/False нечувствительны к регистру; пустые часы → `null` (ограничение не применяется). Zod проверяет каждую запись, дубли ID, поля и даты; ошибки содержат номер логической CSV-записи и поле. Проверяются сводные количества и SHA-256. Скрипт выводит точные количества по категориям.

Для другого расположения укажите в `.env.local`:

```dotenv

```

Next.js и команды проверки читают `.env.local`. Исходный файл намеренно исключён из автоматической трассировки файлов сборки; в локальном production-запуске он читается по `DATASET_PATH`. При любой будущей разрешённой публикации его нужно отдельно предоставить серверу по согласованным правилам.

## Архитектура и точный алгоритм

```text
Russian React form
  → POST /api/recommend (Next.js Node route handler)
  → ограничение тела 4096 байт + Zod + нормализация
  → серверный CSV-кэш (путь, размер, mtime, ctime)
  → город + категория
  → календарь + цена + формат + язык + часы
  → стабильное ранжирование → максимум 3 ID
  → факты + объяснения по правилам
  → [опционально] один AI-запрос → валидация / fallback
  → карточки + диагностика + источник объяснения
```

Функции в `lib/matching.ts` чистые и тестируются без Next.js и ключа. Совпадения строк нормализуются через NFKC, trim, схлопывание пробелов и lower-case `ru`. Опции формы строятся из фактических полей CSV. Сервер канонизирует выбранные опции, ограничивает строки, числовой бюджет (1…1 000 000 000 ₸), целые часы (1…168) и календарную дату.

Жёсткие ограничения одинаковы для всех, **включая площадки и банкетные залы**. Дата в `busy_dates` всегда исключает профиль. Стартовая цена не выше бюджета. Формат и язык должны быть явно перечислены. Часы исключают профиль только при ненулевом лимите и превышении этого лимита.

Рейтинг: **`score = 30 × (budgetKzt − priceFromKzt) / budgetKzt`**, затем `score DESC`, `priceFromKzt ASC`, `id ASC` с явным сравнением строк. Внутри одного запроса это предпочтение большего запаса бюджета, а не заявление о качестве. Описания, случайность, текущее время и LLM не влияют на порядок. Одинаковые нормализованные запросы дают одинаковые ID в том же порядке.

| Статус | Значение |
|---|---|
| `matched` | Есть хотя бы один подходящий профиль, показано 1–3 |
| `no_category_in_city` | В городе нет ни одного профиля категории |
| `no_eligible_candidates` | Категория есть, но все профили исключены ограничениями |

Диагностика рассчитывается только среди профилей выбранного города и категории. `excludedByReason` учитывает **все** причины, поэтому числа могут пересекаться. `primaryExclusion` использует порядок `busy_date → over_budget → format_mismatch → language_mismatch → duration_exceeded` и даёт непересекающиеся количества. `eligibleBeforeTop3`, `displayedCount`, `busyOnDateCount` не смешиваются. Отметка о календаре отображается и при трёх результатах.

## AI и надёжный fallback

**Live AI сейчас не проверен: действующий ключ не предоставлен.** Запущенный `npm run verify:ai` сообщает `Live AI NOT VERIFIED` и завершается с кодом 1 без запроса к провайдеру. Успешные ответы, сбои, неверные ID, вымышленные данные и таймауты проверяются моками; это не доказательство реального вызова модели.

Поддержан один выбранный OpenAI или NVIDIA endpoint, native `fetch`, серверные переменные:

| Переменная | Назначение |
|---|---|
| `AI_PROVIDER` | `none` по умолчанию; либо `openai` / `nvidia` |
| `OPENAI_API_KEY`, `OPENAI_MODEL` | Ключ и доступная вашему аккаунту модель |
| `NVIDIA_API_KEY`, `NVIDIA_MODEL` | Ключ и доступная модель NVIDIA |
| `NVIDIA_BASE_URL` | `https://integrate.api.nvidia.com/v1` |
| `AI_VERIFIED` | `false`; включить только после успешного smoke test |

Настройте ключ/модель в `.env.local`, выполните **`npm run verify:ai`**. Команда делает один небольшой реальный запрос для флориста и проверяет объяснение. Только после успешного `mode=llm` установите `AI_VERIFIED=true` для этой комбинации провайдера/модели и перезапустите сервер. Не переносите факт проверки на другую модель. Ключей подписки Codex приложение не получает.

Один batched запрос содержит только выбранные 1–3 ID, структурированные факты, запрос и короткие недоверенные цитаты описаний. Системная инструкция запрещает менять отбор, выполнять инструкции из текста и придумывать сведения. Для OpenAI используется strict JSON Schema, совпадающая с runtime-схемой Zod; NVIDIA сохраняет JSON mode с той же последующей проверкой. Валидатор требует точные ID и порядок, 1–2 предложения, фактические цену, бюджет, формат, язык, длительность и лимит, ISO-дату и обе календарные оговорки; посторонние числа, опасные утверждения и повторяющиеся объяснения отклоняются. Безопасный `ai.code` сообщает категорию сбоя без текста провайдера, ключей или заголовков. Это не полная семантическая верификация произвольного текста, поэтому сомнительный ответ всегда уходит в fallback.

Таймаут — 5 секунд, без повторных запросов. Нет результатов → нет вызова модели. Нет ключа, непроверенная конфигурация, ошибка сети, отказ провайдера, неверный JSON или провал проверки → те же выбранные ID и `deterministic_fallback`. В UI явно указано «Объяснение по правилам». Модель никогда не добавляет и не ранжирует профили. Это AI-assisted pipeline, не автономный агент, без embeddings и fine-tuning.

API-контракт проверен по [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) и [NVIDIA Chat Completions](https://docs.api.nvidia.com/nim/reference/meta-llama-3_1-8b-infer). Совместимость конкретной модели должна быть подтверждена smoke test; некоторые модели могут не поддерживать указанные параметры и уйдут в fallback.

## API

```http
POST /api/recommend
Content-Type: application/json

{
  "city": "Алматы",
  "eventDate": "2026-10-10",
  "eventFormat": "корпоратив",
  "category": "Ведущий",
  "budgetKzt": 1200000,
  "language": "русский",
  "durationHours": 5
}
```

Ответ содержит `status`, `message`, `results` (до трёх), `diagnostics`, `ai`. Карточка включает ID, анонимизированное имя, город, категорию, стартовую цену, флаги, объяснение, `explanationSource` и ограниченные факты `evidence`. Полный CSV/полные профили не отдаются. Опции передаются сервером странице, отдельный API списка не нужен.

Ошибки: 400 — неверные поля/дата/JSON, 413 — тело больше 4096 байт, 415 — не JSON, 503 — недоступен исходный каталог. Клиент ограничивает ожидание 12 сек, отключает повторную отправку, показывает ошибки и кнопку повтора.

## Ограничения, безопасность и лицензии

- Цены **от**, не финальные сметы. Отсутствие занятой даты — лишь запись в календаре, не подтверждение брони. Вне известного окна запрос отклоняется.
- Синтетические профили и восстановленные цена/город явно помечаются. Описания — утверждения исходного профиля, не независимая проверка. React отображает текст с экранированием, без `dangerouslySetInnerHTML`.
- `.env.local`, CSV, сборки, отчёты и screenshots игнорируются Git. Секреты доступны только серверу; ошибки провайдера и стеки не возвращаются клиенту. Рекомендуемый локальный запуск не использует внешние шрифты, аналитику или изображения. При включении AI факты выбранных профилей отправляются выбранному провайдеру.
- Нет публичного развёртывания и production rate-limit/auth: приложение подготовлено для локального жюри. Перед отдельным разрешённым публичным запуском нужны согласованные права на данные и защита платного API от злоупотреблений.
- Проект создан с помощью Codex в рабочем окне 23.09.2026; реальные checkpoint-времена и SHA указаны в PROGRESS. Никаких обученных моделей, embeddings, шаблонов сайта или проверенного live AI не заявлено. Иллюстрация в UI — CSS/SVG, внешние assets не использованы.
- Исходный репозиторий не содержал лицензии приложения; лицензия организаторских данных неизвестна. Зависимости сохраняют свои лицензии: Next.js, React, Tailwind, csv-parse, Zod, Vitest, tsx — MIT; TypeScript и Playwright — Apache-2.0; `server-only` — MIT. Точные тексты см. в установленных пакетах и lockfile.
- При использовании live API действуют условия [OpenAI](https://openai.com/policies/services-agreement/) или [NVIDIA API Catalog](https://www.nvidia.com/en-us/agreements/enterprise-software/nvidia-api-catalog-terms-of-service/). Квоты, стоимость, модель и разрешение на передачу данных должны соответствовать вашему аккаунту; приложение их не обещает.

Публикация, последующие push, PR, merge, deployment и финальная сдача выполняются только после отдельного явного разрешения участника. Официальная процедура отчётности/сдачи организаторами пока не предоставлена; наличие push само по себе не доказывает сдачу.
